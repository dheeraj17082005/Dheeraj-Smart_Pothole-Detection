# Functionality Gap Register — PotholeX

This register documents all potential gaps, defects, or inconsistencies evaluated during STEP 47, along with root causes, technical fixes, verification tests, and final status.

| ID | Feature | Current Problem | Root Cause | Fix | Test | Final Status |
|----|---------|-----------------|------------|-----|------|--------------|
| GAP-01 | Status Transition Modal | Status update modal failed to submit target status when opened for multiple potholes | `selectedStatus` React state was initialized once without `useEffect` reset on `isOpen` or `currentStatus` change | Added `useEffect` in `StatusUpdateModal.tsx` to reset `selectedStatus`, `changedBy`, and `notes` when modal opens | Tested status modal transition from ACCEPTED → IN_PROGRESS → RESOLVED | **PASS** |
| GAP-02 | Anonymous Evidence Upload | `/detect-image` & `/detect-video` permitted unauthenticated access | Missing authentication filter rule on detection endpoints | Added `.requestMatchers("/api/v1/potholes/detect-*").authenticated()` to `WebSecurityConfig.java` | Direct `curl` without Bearer token returns HTTP 401 Unauthorized | **PASS** |
| GAP-03 | Status Update Authorization | Status update API `/potholes/{id}/status` could be called by citizen role | Endpoint only checked authentication without `@PreAuthorize("hasAuthority('ROLE_OFFICER')")` | Added `@PreAuthorize("hasAuthority('ROLE_OFFICER')")` on controller endpoint and `PotholeStatusTransitionService` | Citizen JWT calling status endpoint returns HTTP 403 Forbidden | **PASS** |
| GAP-04 | Unverified Officer Access | Officers with `PENDING_VERIFICATION` could view jurisdiction reports | `getReportsInJurisdiction` did not enforce verification status check | Added `validateVerifiedOfficer` in `OfficerService.java` and `PotholeStatusTransitionService.java` | Pending officer JWT calling `/officer/reports` returns HTTP 403 Forbidden | **PASS** |
| GAP-05 | Rejection Workflow Audit | Rejection details were not visible to citizens on report detail page | `PotholeDetailPage.tsx` did not render rejection reason or notes | Added structured Rejection Alert card in `PotholeDetailPage.tsx` | Rejected report displays reason, officer note, and timestamp | **PASS** |
| GAP-06 | 30-Day Resolved Duplicate Gate | Submissions near recently resolved potholes created duplicate tickets | `DeduplicationService` ignored resolved status in candidate query | Enforced 30-day resolution window check returning `POTHOLE_ALREADY_RESOLVED` notice | Uploading image near pothole resolved 5 days ago returns resolved notice | **PASS** |
| GAP-07 | Zero-Detection Evidence Handling | Images with 0 potholes created empty pothole records | `processImageDetection` did not handle zero count cleanly | Handled `potholeCount == 0` to return `NO_POTHOLE_DETECTED` state (`potholeCount: 0`) without creating normal pothole record | Uploading non-road image returns clean `NO_POTHOLE_DETECTED` result | **PASS** |
| GAP-08 | Legacy Identity References | Hard-coded "Inspector Rajesh" appeared in modal defaults | Legacy prototype default string in component initial state | Replaced hard-coded identity with `user?.fullName || 'Municipal Officer'` | Inspected status modal defaults across all user roles | **PASS** |
